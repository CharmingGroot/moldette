# Contributing to moldette

moldette is maintained by one person. To keep reviews manageable, pull
requests are accepted only for issues the maintainer has assigned (#12).

## Issues

Bug reports and proposals are welcome as issues, in English or Korean. Use the
issue forms; they ask for the version, the configuration and the input needed
to reproduce a problem.

Do not report vulnerabilities in a public issue. Follow `SECURITY.md` instead.

Design decisions are recorded as issues labeled `type:decision`. Read the
decisions for the layer you want to change before proposing a different
approach.

## Pull requests

1. Open an issue, or comment on an existing one, describing the change.
2. Wait until the maintainer assigns the issue to you.
3. Open one pull request for that issue, with tests.

Pull requests without an assigned issue, and pull requests generated by
automated tools, are closed without review.

AI-assisted contributions are accepted within an assigned issue. You must be
able to explain every change in the pull request, and you must have run the
tests yourself.

## Commits

Every commit must carry a Developer Certificate of Origin sign-off
(https://developercertificate.org/). Add it with `git commit -s`; the name and
email must be your own.

Commit messages follow Conventional Commits (`feat:`, `fix:`, `docs:`,
`chore:` and so on) in English or Korean. Pull requests are squash-merged, and
the pull request description becomes the commit message, so describe the
background first and then the changes.

## Development

The crates depend on each other in one direction:

    moldette -> moldette-config -> parser, mapper, resp -> moldette-core

A layer crate must not depend on another layer crate, and `moldette-core` must
not depend on any of them. Library crates perform no I/O, keep no global state
and build for `wasm32-unknown-unknown`. The minimum supported Rust version is
1.88.

Before opening a pull request, run for each crate you changed:

    cargo fmt --all
    cargo clippy -p <crate> --all-targets --all-features
    cargo test -p <crate> --all-features
    cargo build -p <crate> --target wasm32-unknown-unknown

Changes to the parser, mapper or resp layers can change the number of
allocations per record, which is checked by the tests in `benches/*/tests`.
